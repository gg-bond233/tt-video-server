# TT Video 视频平台后端

TT Video 是一个视频平台的后端服务，基于 Spring Boot 3 构建，为前端提供用户端与管理端两套 RESTful API。

## 技术栈

- **Java 17** + **Spring Boot 3.3.7**
- **MyBatis-Plus** + **MySQL**（Druid 连接池）
- **Redis**：缓存热点数据，减轻数据库压力
- **MinIO**：对象存储，存放视频、封面与轮播图文件
- **JWT** + **拦截器**：登录认证与基于角色（RBAC）的接口鉴权
- **Spring Mail**：邮箱验证码发送

## 功能模块

### 用户端

- 注册 / 登录（邮箱验证码）、个人信息与密码管理
- 视频浏览、详情查看、分类查询
- 视频评论、点赞、收藏
- 轮播图展示、意见反馈

### 管理端

- 管理员登录与鉴权
- 用户管理：查询、搜索、启用 / 禁用
- 视频管理：新增（含封面、视频文件上传）、编辑、删除、上下架
- 轮播图管理：关联视频、控制展示状态

## 项目亮点

### 统一认证与鉴权体系

- 基于 **JWT** 实现无状态登录认证，服务端无需存储会话，天然支持水平扩展
- 自定义 `LoginInterceptor` 拦截器统一校验 Token，并通过 **ThreadLocal** 传递当前用户上下文，业务代码无需重复解析 Token
- **RBAC 角色权限模型**：角色与接口路径的映射关系集中配置在 `application.yml`（`role-path-permissions`），新增角色或调整权限无需改动代码
- 登录态信息通过 Redis 存储，支持主动登出即时失效

### 多层缓存设计

- 使用 **Spring Cache**（Redis）注解驱动的方式缓存高频读取数据（如视频列表、详情），统一配置 TTL，降低数据库压力
- 缓存 TTL 从配置文件读取，与代码解耦，便于不同环境调整策略

### 文件存储与业务解耦

- 视频文件、封面图统一上传至 **MinIO** 对象存储，服务端只保存访问 URL，应用服务器不存放大文件
- 上传逻辑与业务逻辑分离（`MinioService` 独立封装），切换存储方案时业务层零改动

### 统一响应与全局异常处理

- 所有接口返回统一的 `Result<T>` / `PageResult<T>` 结构，前端处理逻辑一致
- `GlobalExceptionHandler` 全局兜底异常（参数校验失败、业务异常、未知异常），避免堆栈信息泄露，返回规范的错误码与提示

### 参数校验与规范分层

- DTO 层使用 **JSR-303 校验注解**（`@NotBlank`、`@Email` 等）配合统一校验工具，非法参数在进入业务层前即被拦截
- 代码分层清晰：Controller（参数接收/校验）→ Service（业务逻辑）→ Mapper（数据访问），DTO / Entity / VO 三种模型各司其职，避免实体直接暴露给前端

## 工程化

- 拦截器路径、跨域、MyBatis-Plus 分页插件等均通过配置类集中管理，结构清晰易于扩展
- 邮箱验证码通过常量类与工具类统一管理，发送超时、重试等异常场景均有兜底处理
